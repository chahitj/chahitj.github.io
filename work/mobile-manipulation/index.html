Coffee preparation task

Coffee preparation is a sequence of dependent manipulation stages: place the mug, open the pod slot and drawer, pick up the pod, then insert it. A missed grasp or placement changes the state seen by every later action.

I investigated learning this sequence in simulation, moving from an atomic mug task through RoboCasa PrepareCoffee to a custom robosuite task. Each phase changed the environment or data available and led to the next approach.

Task stages

Frames from the approved V1 BC-RNN rollout show the task progression.

Demonstration data

The final custom robosuite task used a simulated Panda arm. My data-collection system tracked semantic task stages, saved exact MuJoCo state after stable subtasks, and let an operator retry only the failed stage. Fifteen source demonstrations then produced 1,887 MimicGen attempts, of which 1,000 successful trajectories were retained for BC-RNN training.

MimicGen trajectory filtering

MimicGen adapted a small source set into many task-consistent trajectories, with simulation outcomes used to filter failures before training.

From exploration to imitation

Reinforcement-learning attempt

SAC with curriculum learning did not reliably acquire the initial grasp after roughly 3.5 million steps. Dense reward shaping did not fix the exploration problem, so more reward tuning was unlikely to solve the multi-stage task.

Small-data imitation

A BC-Transformer trained on 54 RoboCasa PrepareCoffee demonstrations reduced training loss but failed in closed-loop rollout. Approaching the right object was not enough; grasp and placement timing broke the sequence.

Collecting complete demonstrations

I built a 6-DoF teleoperation interface with gripper and task controls. The collector marked semantic stages, saved exact MuJoCo state after stable subtasks, and restored that state when a later stage failed. Accepted segments kept their lineage when assembled into a complete demonstration, so a missed pod grasp did not require recollecting the mug-placement stages.

Corrective collection

I added policy/human control handoff for DAgger-style corrective collection and gathered roughly 50 corrective demonstrations in simulation. This created a separate path for capturing recovery behavior during policy execution.

Scaling demonstrations with MimicGen

Fifteen source demonstrations from that workflow seeded MimicGen. It generated 1,887 trajectory attempts; simulation-success filtering retained 1,000 for BC-RNN training.

Research progression

Each failed rollout exposed a different bottleneck and motivated the next data-collection and policy design.

Failure analysis

What did not work

The randomized setting did not converge within available compute. SAC failed to bootstrap the initial behavior, and the 54-demo BC-Transformer failed in closed-loop rollout despite lower training loss. Those failures motivated staged data collection, MimicGen scaling, and the recurrent policy.
